> کد بومی، پچ، یا ترکیبی از هر دو — تا نتیجه همه‌جا بهترین باشد و این دو سازوکار با هم نجنگند.

## ۱. Anthropic چه چیزی را عوض کرد (یافته‌های بررسی)

### ۱.۱ این کد کجا اجرا می‌شود

برنامهٔ دسکتاپ **تمام** محتوای گفتگو و کد را از claude.ai بارگذاری می‌کند (در `index.html` داخل asar
صریحاً نوشته شده: *"everything else gets loaded from claude.ai"*). پس تغییر Anthropic روی وب زندگی می‌کند،
خودبه‌خود به دسکتاپ می‌رسد، و نمی‌شود آن را به‌صورت یک فایل ایستا ورق زد — فقط از راه DOM زنده یا باندل‌ها.

### ۱.۲ الگوریتم آن‌ها (استخراج‌شده از باندل، چانک `c06173196`)

دو رندرر جدید markdown («alluvium») هنگام رندر، `dir` را می‌نشانند:

- **`B_`** — رندرر زبانهٔ Code (استریم با word-fade، `data-alluvium`). **فعال.**
- **`sP`** — رندرری با تایپوگرافی `font-claude-response-body` — همان کلاس‌های گفتگوی معمولی.
  در باندل هست اما **هنوز فعال نیست** (انتشار تدریجی / feature flag). یعنی RTL بومی در گفتگوی
  معمولی احتمالاً در راه است.

منطق کار (نام‌های فشرده‌شدهٔ `fT`/`gT`/`uT`، فقط داخل همان استقرار پایدارند):

<div dir="ltr">

```
dir = fT(gT(block))     // اعمال می‌شود روی: p, h1-h6, ul/ol, blockquote, پوشش جدول, footnoteDef
                        // اعمال نمی‌شود روی: fence (کد), hr, math, سلول جدول, li, پیام‌های کاربر

fT(text):               // first-strong سادهٔ روی متن
  هر نویسه: RTL اگر 0x0591-0x07FF / presentation forms / RLM,RLE,RLO
            LTR اگر A-Z a-z / لاتین گسترده (192-696) / یونانی-سیریلیک-ارمنی (880-1424)
  وگرنه: undefined  → اصلاً ویژگی dir گذاشته نمی‌شود

gT(block):              // چه متنی اسکن می‌شود — فقط ۸۰ نویسهٔ اول
  paragraph  → به‌هم‌چسباندن سطرها
  heading    → متن
  list       → فقط فرزند اول از آیتم اول (!)
  blockquote → فرزند اول
  table      → فقط سلول سرستون اول (!)
  fence/hr/math → "" (بدون dir)

uT (استخراج متن): کد درون‌خطی، kbd، math و fileUrl را هم در متن اسکن‌شده می‌آورد (!)
```

</div>

افزون بر این: `unicode-bidi: isolate` به‌صورت فراگیر روی همهٔ بلوک‌ها، و سلول‌های جدول با `text-align:left` سفت‌وسخت.

### ۱.۳ نقشهٔ پوشش — بومی در برابر واقعیت

| سطح | RTL بومی؟ |
|---|---|
| زبانهٔ Code — بلوک‌های markdown پاسخ‌ها | ✅ `dir` برای هر بلوک |
| زبانهٔ Code — سلول جدول، li، بلوک کد | ❌ (عمدی — بدون dir) |
| زبانهٔ Code — **پیام‌های کاربر** | ❌ (`csDir:ltr`، بدون dir) |
| گفتگوی معمولی — همه‌چیز (پاسخ‌ها + پیام‌های کاربر) | ❌ (رندرر قدیمی؛ `sP` در باندل منتظر است) |
| کادرهای ورودی (ProseMirror) — همه‌جا | ❌ (`ltr` + `unicode-bidi:isolate`) |
| رابط کروم — نوار کناری، عنوان گفتگوها، دیالوگ‌ها | ❌ |
| پنجرهٔ ویندوز (نوار عنوان و…) در حالت فارسی/عبری | ❌ (همان باگ قدیمی — پچ هنوز لازم است) |

### ۱.۴ مقایسهٔ دقت: بومی در برابر پچ

| سناریو | بومی | پچ |
|---|---|---|
| بند سادهٔ فارسی/انگلیسی | ✅ | ✅ |
| متن فارسی که با نام فایل / کد درون‌خطی / URL شروع می‌شود | ❌ `ltr` | ✅ |
| فارسی که فقط بعد از ۸۰ نویسه ظاهر می‌شود | ❌ | ✅ |
| بند چندسطری با زبان‌های مخلوط | ❌ یک dir برای همه | ✅ plaintext برای هر سطر |
| فهرست فارسی که آیتم اولش انگلیسی است | ❌ | ✅ رأی اکثریت |
| جدول فارسی که سرستون اولش انگلیسی است | ❌ | ✅ رأی اکثریت |
| سلول‌های جدول | ❌ | ✅ برای هر سلول |
| محاسبات و LaTeX داخل بند فارسی | ❌ | ✅ جزیرهٔ جداشده |
| پیام‌های کاربر / ورودی / رابط | ❌ | ✅ |
| پایداری هنگام استریم (بدون لرزش) | ✅ در زمان رندر | ⚠️ واکنشی (۵۰ms) |

نتیجه: کد بومی تقریباً معادل «لایهٔ ۱» پچ است، با برتری پایداری در استریم. ادغام، پایداری آن‌ها را در
حالت ساده می‌گیرد و دقت پچ را در بقیهٔ موارد. یک نکته هم از آن‌ها به پچ برگشت: نویسه‌های کنترلی
RLM/RLE/RLO/RLI به `RTL_RANGES` به‌عنوان RTL قوی اضافه شدند.

### ۱.۵ چرا پچ در زبانهٔ Code به‌هم می‌ریخت

۱. **`resetDirOrPinLTR` ویژگی `dir` بومی را پاک می‌کرد.** بندی انگلیسی که Anthropic با `dir="ltr"`
   علامت زده بود: `detectElDir` مقدار null برمی‌گرداند (RTL ندارد) → تابع ویژگی dir را حذف می‌کند.
   React هنگام استریم دوباره می‌گذارد → پچ دوباره پاک می‌کند → جنگ.
۲. **`splitToDirectionalSpans` هم `dir` بومی را** از بندهای چندسطری پاک می‌کرد.
۳. **استریم alluvium:** بلوک‌های لبه مدام از نو رندر می‌شوند؛ هر دست‌کاری DOM از سوی پچ
   (جزیره‌ها، جایگزینی گره‌های متنی) داخلشان مدام بازنویسی و دوباره اعمال می‌شود — همان churnای
   که به‌چشم خرابی می‌آید.
۴. **CSS فراگیر:** قاعدهٔ `[dir]>*:not([dir])…{unicode-bidi:plaintext}` حالا روی فرزندان بلوک‌های
   بومی هم می‌افتد (که ساختار دیگری دارند — span‌های word-fade) — برهم‌کنشی پیش‌بینی‌نشده.

## ۲. ماتریس ادغام — حوزه به حوزه

**اصل مالکیت (روی همه‌چیز اعمال می‌شود):** هر `dir`ای که پچ می‌گذارد با `data-rtl-managed="1"` علامت
می‌خورد. ویژگی `dir` بدون این علامت یعنی بومی. بومی را **هرگز** پاک یا «بازنشانی» نمی‌کنیم.

| # | حوزه | بومی چه می‌کند | پچ چه می‌کند | کدام بهتر است | قاعدهٔ ادغام |
|---|---|---|---|---|---|
| ۱ | جهت بلوک‌ها (p, h*, blockquote) | first-strong روی ۸۰ نویسه، **شامل** کد درون‌خطی/URL | ۳ لایه: بدون `<code>` → حذف پیشوند LTR → اکثریت نویسه‌ها | پچ در حالت‌های مرزی؛ بومی در اکثر موارد کافی است | dir بومی هست و پچ موافق است → دست نمی‌زنیم. dir بومی نیست → پچ طبق روال. بومی `ltr` گفته ولی تشخیص (با لایهٔ اکثریت) می‌گوید `rtl` → بازنویسی علامت‌دار. بلوک بومی چندسطری مخلوط → plaintext برای هر سطر بدون دست‌زدن به dir |
| ۲ | بندهای چندسطری چندزبانه | یک dir بر اساس ۸۰ نویسهٔ اول — سطرهای زبان دوم می‌شکنند | `unicode-bidi:plaintext` برای هر سطر | **پچ** | plaintext را در style اضافه می‌کنیم **بدون حذف** dir بومی (برای پایداری React می‌ماند)؛ حذف فعلی فقط برای dirهای متعلق به پچ باقی می‌ماند |
| ۳ | فهرست‌ها (ul/ol/li) | dir روی ul/ol فقط بر اساس **آیتم اول**؛ li بدون dir؛ padding فیزیکی | dir برای هر li + برگرداندن padding + list-style-position | **ترکیبی** | ul/ol: مثل قاعدهٔ ۱. li: بومی ندارد → همیشه پچ (افزودنی خالص). برگرداندن padding: فقط وقتی padding واقعاً سمت اشتباه باشد |
| ۴ | جدول‌ها — برگرداندن ستون‌ها | dir روی پوشش بر اساس **فقط سلول سرستون اول** | رأی اکثریت روی سرستون‌ها + ستون اول (`tableDirFromCells`) | **پچ** (تشخیص) / بومی (جایگذاری) | پوشش با dir بومی → برگرداندن انجام شده، دست نمی‌زنیم. بومی جا انداخته (سرستون اول انگلیسی، جدول فارسی) → پچ `dir` را روی خودِ `<table>` می‌گذارد (علامت‌دار، نه روی پوشش آن‌ها) |
| ۵ | جدول‌ها — سلول‌ها | هیچ: rtl را ارث می‌برند، `text-align:left` سفت — سلول LTR قاتی می‌شود و اعداد می‌شکنند | `cellDir` برای هر سلول (شامل‌بودن RTL، نه فقط first-strong) | **قطعاً پچ** — مهم‌ترین تقویت | پچ برای هر th/td یک `dir` علامت‌دار بر اساس محتوا می‌گذارد و `text-align:start` می‌دهد. افزودنی خالص — سلول‌ها dir بومی ندارند. هم در جدول‌های بومی کار می‌کند هم در گفتگو |
| ۶ | LaTeX خام + محاسبات (`2+3=5` که برمی‌گردد) | هیچ (در گفتگوی دسکتاپ LaTeX رندر نمی‌شود؛ محاسبه داخل بند فارسی آینه می‌شود) | جزیرهٔ `unicode-bidi:isolate` (`segmentText`) | **پچ — توانایی منحصربه‌فرد** | همه‌جا می‌ماند. به dir دست نمی‌زند پس تعارضی ندارد. تنها استثنا: **رد‌شدن از بلوک‌های لبهٔ alluvium** (استریم فعال) — فقط بعد از تثبیت بلوک پردازش می‌شود تا با رندر مکرر نجنگد |
| ۷ | بلوک‌های کد (pre/fence) | بدون dir (عمدی)؛ اما fence داخل li یک فهرست rtl بدون محافظ rtl را ارث می‌برد | `forceCodeLTR` + CSS که ltr را قفل می‌کند | **پچ** (کمربند ایمنی) | بدون تغییر می‌ماند — بومی هیچ‌وقت روی کد dir نمی‌گذارد، برخوردی نیست |
| ۸ | پیام‌های کاربر (هر دو زبانه) | **هیچ** — حتی در زبانهٔ Code | مدیریت کامل | **پچ** | کامل می‌ماند |
| ۹ | کادرهای ورودی | هیچ (`ltr` ثابت) | تشخیص زنده هنگام تایپ | **پچ** (آزموده و درست) | بدون تغییر می‌ماند |
| ۱۰ | رابط کروم (نوار کناری، دیالوگ‌ها، tooltipها) | هیچ | `processContainers` | **پچ** | می‌ماند، با محافظ تازه: رد‌شدن از عناصری که زیر زیردرختِ dir بومی هستند |
| ۱۱ | پنجرهٔ RTL ویندوز (فرایند main) | ربطی به این تغییر ندارد | اصلاح نوار عنوان | **پچ** | بدون تغییر |
| ۱۲ | CSS تزریقی | `isolate` فراگیر خودشان | برگهٔ قواعد فراگیر | ترکیبی | بازبینی قاعده‌به‌قاعده: قواعدی که به `[dir]` دست می‌زنند به `[dir][data-rtl-managed]` محدود می‌شوند، مگر آنکه به نفع بومی هم باشند (مثل `text-align:start` برای سلول‌ها). قاعدهٔ فراگیر `[dir]>*` به مالکیت پچ محدود شد |

## ۳. تغییرات مشخص در `rtl-payload.js`

۱. **`MANAGED_FLAG`** — ثابت تازهٔ `data-rtl-managed`؛ کمکی `stampDir(el, dir)` که dir را همراه علامت
   می‌گذارد، و `isNativeDir(el)` (`hasAttribute('dir') && !hasAttribute(MANAGED_FLAG)`).
۲. **`resetDirOrPinLTR`** — dir بومی را نه حذف می‌کند نه تغییر می‌دهد؛ فقط روی عناصر متعلق به پچ یا
   بدون dir کار می‌کند.
۳. **`splitToDirectionalSpans`** — dir را فقط اگر متعلق به پچ باشد حذف می‌کند؛ بومی می‌ماند و فقط
   plaintext می‌گیرد.
۴. **`processText`** — در ابتدای حلقه: `isNativeDir(el)` → مسیر «بومی»: بررسی اختلاف (تشخیص کامل —
   لایهٔ ۳ مبتنی بر اکثریت نویسه‌ها، نه «هر نویسهٔ RTL») یا plaintext برای بلوک‌های چندسطری مخلوط،
   و نه بیشتر. وگرنه همان مسیر قبلی، با `stampDir`.
۵. **`processTables`** — تشخیص «قبلاً به‌صورت بومی برگردانده شده» (پوشش یا جدول با dir بومی یا rtl
   محاسبه‌شدهٔ ارثی) → رد‌شدن از برگرداندن؛ **تازه:** حلقهٔ سلول‌ها — `stampDir` برای هر th/td بر اساس
   `cellDir`، در هر جدولی (بومی یا نه).
۶. **`processContainers`** — محافظ: `el.closest('[dir]:not([data-rtl-managed])')` → رد‌شدن.
۷. **`isolateMath`** — محافظ استریم: رد‌شدن از متن داخل بلوک لبهٔ alluvium.
۸. **CSS** — تفکیک قواعد `[dir]` بر اساس مالکیت، طبق سطر ۱۲ ماتریس.
۹. **MutationObserver** — بهینه‌سازی: تغییری که تماماً داخل زیردرخت بومیِ موافق باشد → no-op زودهنگام
   (کاهش churn استریم).

## ۴. نتیجه چه می‌شود

- **زبانهٔ Code:** به‌هم‌ریختگی‌ها از بین می‌رود (نه حذف dir بومی، نه جنگ استریم)، و پچ همچنان همان‌جا
  ارتقا می‌دهد: سلول‌های جدول، liهای مخلوط، محاسبات، پیام‌های کاربر، کادر ورودی.
- **گفتگوی معمولی:** دقیقاً مثل امروز کار می‌کند (مالکیت کامل با پچ).
- **آینده:** وقتی Anthropic `sP` را در گفتگو روشن کند، پچ آنجا خودبه‌خود به همان مدل
  «بومی + تکمیل» عقب می‌نشیند، بدون نیاز به به‌روزرسانی.
- **بدون وابستگی به نام‌های فشرده‌شده:** همهٔ قواعد مبتنی بر DOM‌اند (ویژگی dir + علامت مالکیت)، نه
  `fT`/`B_` و امثال آن‌ها که هر استقرار عوض می‌شوند.
